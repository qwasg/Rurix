### 1.2 M19 相对 G7 的精确增量

G7 交付的是**单帧、单方向光、"脏且驻留页快照"的三段数据面对拍**（mark 位图 / 页内深度 / 采样）。M19 缺口精确为六项：

1. **失效原因分类**：host `vsm.rs` 三源失效只写一个 dirty 位，不留原因；无冻结枚举、无事件记录。
2. **跨帧事件序列 golden**：G7 无 alloc/hit/evict/invalidate 的逐帧 canonical 序列（host 有 `AllocStats.evicted_pages` 等统计，但非序列化 golden）。
3. **clipmap scroll 的门内见证**：host 有 toroidal 环带标脏（`origin_shift_one_page_dirties_ring_band_only` 单测），但从未进入 device 门判据。
4. **local light page**：src 全仓零 local light（已 grep 证实）；host VSM 是单方向光结构。
5. **非虚拟几何 caster**：无 caster 分类概念（VSM 光栅输入是扁平 `ShadowTri` 列表）。
6. **multi-view batch**：host `views()` 有多视图接口，device `vsm_depth_raster.rx` 的 pages buffer 只带 `(origin, page_world, z_range)`，单基单视图；无"多视图一次批量 dispatch"见证。

### 1.3 M24 相对 G7 的精确增量

G7 的 `tsr_temporal.rx` 已是"host TSR 时域臂的逐字 device 化 + 32 帧序列 + 错绑 history RED"。M24 缺口精确为七项：

1. **history resurrection**：host `tsr.rs` 模块文档明写"收敛加速(Resurrection)归后续波次"——**host 侧也没有**，全新算法面。
2. **pixel animation 材质语义**：无材质 IR 时变标记；reactive 在 G7 孤立腿恒 0。
3. **thin geometry**：无 coverage/confidence 判定，深度单判据（RFC-0019 §4.6.3 三条约束全未实现）。
4. **dynamic resolution**：G7 序列 IN 16×16 → OUT 32×32 恒定；host TSR 输出分辨率变化=丢历史，无"输入 extent 逐帧变化且历史存续"的 normalized-viewport 重投影。
5. **transparent velocity**：无透明 velocity/coverage provenance 输入面。
6. **history identity 显式校验**：G7 的 `--frame-red-history` 是绑定纪律 RED（错绑 ping-pong），不是数据化 provenance key（view/generation/epoch/extent/jitter/exposure/interface hash/motion version 八元组）比对。
7. **冻结 golden + tolerance**：G7 tolerance（1e-6）是 raster_diff 门的，M24 须按 RFC-0019 §4.6.3 走"首批 measured corpus → RFC 加性修订行冻结"程序。

## 2. M19 `g8.p0.m19.vsm_page_cache` 设计

### 2.1 架构裁决：host 决策 + device 数据面

判据要求"事件序列与 golden 全等"+"页表/readback depth digest 与 device golden 相等"，**不要求分配决策本身在 GPU**。裁决：页缓存决策（alloc/LRU evict/失效分类）留 host（`rurix-render` 是权威，`forbid(unsafe)` 维持）；mark→depth→sample 三段数据面在 device（承 G7 三核），页表每帧上传、device 消费后 readback 验 digest。帧循环：

```text
每帧：device page_mark(多视图) → readback 位图 → host 分类(hit/miss)+alloc/evict+失效分类 → 事件入日志
     → 上传页表(全灯)+脏页视图批次 → device depth_raster_mv(单 dispatch 多视图 gather)
     → device sample(方向光+local) → readback 页表/depth/sample → 逐帧 digest
```

### 2.2 数据结构扩展（`shadow/` 模块，全部加性）

| 结构 | 设计 | 落点 |
|---|---|---|
| **失效原因枚举**（spec 冻结） | `InvalidationReason { CasterMoved, LightChanged, ClipmapScroll, NonVirtualCaster, Evicted }` 五值闭集。**不进 32 位页表项**（保留位 [26..32) 维持恒 0，G5 冻结面 0-byte，免 RFC 修订）；进 side-band 事件日志 | 新 `shadow/events.rs` |
| **事件日志** | `PageEvent { frame: u32, light: LightId, level: u8, slot: (u8,u8), kind: EventKind, phys: u16 }`；`EventKind { MarkHit, MarkMiss, Alloc, Evict, Deny, Invalidate(InvalidationReason), Raster }`。canonical 序列化 = 确定性 JSON 行（帧升序→灯→级→槽位行主序），golden 为 checked-in 文件 + SHA-256 | 同上 |
| **LightId / 多灯页表集** | `LightId { Directional, Local(u8) }`；`Vsm` 泛化为 per-light 页表组：方向光保留既有 clipmap 级结构（**既有 API 与全部单测 0-byte**，local light 为加性构造函数）；local light 首期 = **1 盏 spot（单视图，透视投影，单级 128×128 页表）**，共享同一 `PhysicalPagePool`（跨灯淘汰竞争真实发生）。omni 6 面不做，记 open | `shadow/local.rs` + `vsm.rs` 加性 |
| **CasterClass** | `ShadowCaster { tris, class: CasterClass{Virtual, NonVirtual}, aabb }`；语义：Virtual caster 仅移动时经 `invalidate_aabb`（reason=CasterMoved）；NonVirtual caster 覆盖页**逐帧强制失效**（reason=NonVirtualCaster，对齐 R1 §3.4"非 Nanite 失效成本更高"） | `vsm.rs` 加性 |
| **multi-view batch 描述** | `ShadowViewBatch`：视图表（方向光 4 级 + local 1 视图）+ per-view 灯空间预变换三角形段 `(tri_offset, tri_count)` + 脏页记录 `(view_id, origin, page_world/透视参数, z_range, phys)`——单 buffer 单 dispatch | `vsm.rs` `views()` 泛化 |

| kernel | 内容 | 形态要点 |
|---|---|---|
| `vsm_page_mark_project.rx`（新） | 反投影+选级+出窗回退搬进 device（G7 的 mark 只做位图 set，page id 由 host 预计算）；复用 `vsm_sample.rx` 已验证的选级/回退环代码形状；输出 per-light 位图 | intrinsic 上提纪律；local spot 臂 = 透视除法+视锥测试 |

### 2.4 fixture：固定多帧多视图脚本（16 帧，判据六命中逐帧对号）

场景 = 地面 + 悬浮板（Virtual caster）+ 摆动小方块（NonVirtual caster）+ 方向光（4 级 clipmap）+ 1 盏 spot。脚本（确定性，全部参数冻结进 harness）：

| 帧 | 动作 | 命中判据 |
|---|---|---|
| F0 | 初始 | 全 miss→Alloc→Raster |
| F1–F2 | 完全静止 | **跨帧 cache hit**（MarkHit>0，Alloc=Evict=Raster(Virtual 区)=0） |
| F3 | 悬浮板平移 | Invalidate(CasterMoved) |
| F4 | 相机沿 +x 平移恰一页 | Invalidate(ClipmapScroll)（0 级一行 128 槽环带） |
| F5 | 灯方向微转 | Invalidate(LightChanged) 全脏 |
| F6–F7 | 静止（重建后再命中） | 二次 cache hit（失效恢复后仍缓存） |
| F8–F11 | NonVirtual 方块摆动 | Invalidate(NonVirtualCaster) 逐帧；Virtual 区页保持命中（增量语义对照） |
| F12 | spot 亮起/移动 | **local-light page** Alloc + local 视图入批 |
| F13–F14 | 标记页数 > 池预算（收紧 pool_pages 的第二配置轮） | Evict（确定性驱逐序）+ Deny |
| F15 | 静止收尾 | 终态页表/depth digest |

多视图：F12 起每帧 5 视图（4 clipmap + 1 spot）single-dispatch 批光栅——**multi-view batch** 命中。golden 双件：① 事件序列 canonical JSON（host 权威产生，checked-in）；② 逐帧页表 digest + depth/sample readback digest（device 对 host 零容差已有 G7 基础，故 device golden = 与 host oracle 相等的 digest，首跑 measured 后 checked-in）。

## 3. M24 `g8.p0.m24.tsr_contract` 设计

### 3.1 host 语义扩展（`temporal/`，UpscaleInputs 冻结面 0-byte）

新增 `temporal/contract.rs`：`TsrContract` 生产实现（内部富输入集，**不改冻结的 `UpscaleInputs`/`UpscaleBackend`**——M24 是 crate 内生产契约，M25 才是对外 ABI）：

- **history identity**：`HistoryProvenance { view_id, resource_generation, history_epoch, prev_extent, cur_extent, jitter_index, exposure_domain, material_interface_hash, motion_convention_version }`（RFC-0019 §4.6.2 八要素逐字）。每帧比对 stored vs expected：任一不相容 → 相关 sample invalidate（可见降级）；结构性错误（布局/版本）→ fail-closed `Err`。
- **resurrection（最小语义）**：单槽 retired ring——history 被 reject 时该像素旧值退休入 ring（带 age、provenance key、depth/normal 快照、confidence）；后续帧仅当 `age ≤ K`（K 入 budget 不入 stable 面）∧ provenance key 相等 ∧ depth/material 相容时恢复并保留 confidence；跨 camera cut/generation/epoch/interface hash 恢复被禁（RFC §4.6.3）。不做 UE 全量多帧 resurrection。
- **thin geometry**：新增输入分辨率 coverage 通道；标记像素的 history 复用改以 coverage/confidence 判定（深度不单独否决）；丢覆盖帧写显式 low-confidence（非零速度伪装）；**禁邻域 motion 外插**（thin 像素不读邻域 MV）。
- **dynamic resolution**：输入 extent 逐帧可变、历史（输出分辨率）存续；重投影按 §4.6.2 在 normalized viewport 消 current/previous jitter 再映射两帧 extent。
- **pixel animation / transparent**：材质路径二分信号：能供运动的路径提供 velocity+confidence；不能的路径写 reactive/history-reject（禁静默当静态）；透明贡献带显式 velocity/coverage provenance，缺声明 → 走 reactive reject、不继承背后 motion。

### 3.2 device kernel 分解（复用 G7.6 经验；旧核 0-byte，新建）

| kernel | 内容 |
|---|---|
| `tsr_contract.rx`（主核） | `tsr_temporal.rx` 的超集：+reactive/coverage/transparent 输入、confidence 通道（hist 扩 4 通道 RGBA=RGB+confidence）、thin-geometry 分支、动态分辨率 extent push constants、resurrection ring 读取臂 |
| `tsr_retire.rx`（维护核） | retired ring 写入/age 推进（与主核分核，规避编码器"并列 if"边界，控制单核复杂度） |
| 空间核 | 沿用 `tsr_resample.rx`（0-byte），extent 经 push constants 变频 |

harness 沿 `device_frame_temporal.rs` 模式：`execute_with_frame_update` 逐帧 `binding_overrides`（ping-pong）+ `push_constant_overrides`（per-frame extent/jitter/reset）+ `buffer_uploads`（输入图与 provenance meta）；buffer 按最大 extent 预分配。

### 3.3 五 case fixture（每 case 独立确定性序列、独立 digest，恰好五个）

| case | 序列构造 | PASS 断言要点 |
|---|---|---|
| `history_resurrection` | 32 帧：竖条遮挡物左右往返扫过高频背景；背景像素被遮 3–6 帧后重现 | 重现帧从 ring 恢复（收敛快于无 resurrection 对照臂，digest==golden）；插入 camera-cut 帧后同构場景恢复必须不发生（禁跨 cut） |
| `pixel_animation_velocity` | 左半 UV 滚动纹理（解析 velocity 路径）/右半噪声闪烁材质（reactive 路径） | 左区历史累积收敛（误差下降）；右区零拖影；静态区不误伤 |
| `thin_geometry` | 1px 亚像素竖线斜向慢移（半分辨率输入下隔帧丢覆盖） | 线像素走 coverage/confidence 路径；丢覆盖帧 confidence 低且 velocity 不被邻域外插污染（对 host oracle 逐值）；深度判据未单独否决 history |
| `dynamic_resolution` | 输入 extent 序列 64→48→64→56→64（输出恒 128），Halton jitter | extent 变化帧历史**不**被丢弃；normalized-viewport 重投影 digest==golden；对照 RED：直接拿 input-texel offset 当 output motion 必红 |
| `transparent_velocity` | 半透明面片滑过反向移动背景；A 臂声明 velocity/coverage、B 臂缺声明 | A 臂透明贡献按自身运动累积；B 臂走 reactive reject 且不继承背景 motion；两臂各 digest==golden |

### 3.4 history identity 校验与 tolerance 冻结流程

- identity：`HistoryProvenance` 打包为 meta buffer（device 侧随 history 常驻）+ host 每帧 expected 比对。RED 轴 = 注入错误 epoch/generation/interface hash → 输出必须等于 reset 路径（复用历史即红）；错误布局 → `Err`。承接并强化 G7 `--frame-red-history` 先例。
- **tolerance 流程（两段 PR，硬序）**：
  1. **PR-5b-M24-impl**：实现 + fixture + smoke 落地，gate 状态 = RED/未冻结（**不得以"tolerance 待定"跳过**，RFC §4.6.3 字面）；
  2. 真跑产首批 measured corpus（4070 Ti，validation-on，记录 GPU/driver identity）；
  3. **PR-5b-M24-freeze**：RFC-0019 加性修订行冻结五 case golden digest + 逐 case tolerance，与 `g8_budget.json` measured 条目同 PR；此后 gate 才可 GREEN。

## 4. M25 `g8.p1.m25.upscaler_input_abi` 设计

### 4.1 ABI 冻结方案

spec 条款（rendering_platform.md，RXS 顺位）冻结 **UpscalerInputAbi v1**：十项输入（color/depth/motion/exposure/jitter/render extent/output extent/reset/reactive/transparent）逐项的 `(资源类别, 通道数/标量类型, extent 域, required|optional, 语义引用)` 字段闭集 → canonical bytes（复用 RXS-0305 序列化规则思想）→ SHA-256 ABI hash（**复用 `rurix-pkg::sha256` 与 M31 基建，不造第三份**）。现有 `UpscaleInputs` 已覆盖九项（render extent = color 尺寸隐含，条款中显式化），缺 `transparent` 独立槽：以**加性扩展**落地——新 `UpscaleInputsExt { transparent: Option<&ImageF32> }` + trait 加默认方法 `upscale_ext(&mut self, &UpscaleInputs, &UpscaleInputsExt)`（default 委托 `upscale`，既有实现零破坏；冻结 trait 原方法 0-byte）。装配期核验：调用方按 ABI 描述符逐项绑定 resource identity，缺任一 required 输入或调用方/backend ABI hash 不等 → 确定性 `Err`（fail-closed，禁静默补零）。

### 4.2 backend 选型裁决

| 选项 | 评估 | 裁决 |
|---|---|---|
| A. 自研 CAS/FSR1(EASU) 级空间 upscaler `.rx` 核 | 零 license、零 unsafe、零 FFI；单 pass 空间核 ~2 人日；host oracle 可逐值审计 | **做**（第二 backend，证明"切换不改调用侧 ABI"） |
| B. vendor FSR2 FFI | C++ SDK + 大量 unsafe FFI + license/SBOM 审计 + Vulkan interop，≥3 周；判据不要求 vendor | **不做**，记 open 留 RD-041 观察（触发条件维持"vendor SDK 接入需求出现时"） |
| C. M24 产出的 device TSR 经 ABI 路径消费 | 已审计（M24 门全对拍）、真 device、消费全部十项（含 reactive/transparent），是最强非 no-op 证据 | **做**（主 backend） |

推荐 **C 主 + A 副**：两个都是"审计过的非 no-op backend"（各自有 host oracle 逐值对拍与序列 golden），双 backend 经同一 ABI 调用侧切换，直接机验"backend 切换不得改变调用侧 ABI"。stub/no-op 红线由"输出对 host oracle 数值门 + 输出≠任一输入透传"断言封死。

### 4.3 smoke `ci/g8_upscaler_input_abi_smoke.py` checks.* 分解

```text
checks.abi_ten_inputs_enumerated      ABI 描述符字段集合 == 十项闭集
checks.abi_layout_hash_stable         双次构建 canonical bytes/hash 逐字节相等
checks.abi_hash_sensitive             任一项 layout/required 变更 → hash 必变(白盒扰动)
checks.missing_input_fail_closed      逐项摘除 required 输入 → 装配 Err(十次独立)
checks.hash_mismatch_fail_closed      篡改调用方 hash → Err
checks.backend_tsr_consumes_all       主 backend 消费全部 required resource identity(evidence 逐项)
checks.backend_cas_consumes_all       副 backend 同上
checks.output_extent_and_finite       输出 == output extent 且全有限值
checks.sequence_digest_match          两 backend 各自冻结序列 golden(measured 后冻结口径)
checks.backend_switch_abi_identical   切换前后调用侧 ABI hash/绑定代码路径同一(机验)
```

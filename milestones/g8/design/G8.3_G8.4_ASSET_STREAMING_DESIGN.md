## 1. Crate 布局与 CLI 形态裁决

### 1.1 新建两个 crate（推荐），不并入既有 crate

```text
src/rurix-geom-pages/     纯格式 crate：M01 逻辑页 + M04 磁盘/内存双 ABI + RXPZ-LZ1 codec
                          依赖：仅 rurix-pkg（sha256）。#![forbid(unsafe_code)]
src/rurix-asset/          资产管线 crate：canonical CBOR、schema、DDC CAS、glTF 导入、
                          纹理 cook 编排、工具 DAG、BuildManifest；[[bin]] rxcook
                          依赖：rurix-pkg、rurix-geom-pages、rurix-geom-build、image-io、
                          rurix-basis-sys（M83，feature 门控）。lib 部分 forbid(unsafe_code)
src/rurix-basis-sys/      M83 vendor FFI crate（镜像 rurix-physics-sys 先例，见 §3.6）
```

**理由**：

- **不并入 `rurix-geom-build`**：它是聚焦的离线 meshlet/DAG 构建器且依赖 `rurix-render`（ClusterRecord 契约单源）。若页 ABI 放进去，运行时流送器（G8.4 消费方）要拿解码器就得经 `rurix-geom-build → rurix-render` 反向成环。**页格式必须是独立叶子 crate** 才能同时被 cook 侧（rurix-asset）与运行时侧（uc06 harness / rurix-render 下游）消费。
- **不并入 `rurix-render`**：它是运行时库（forbid unsafe、G5 冻结面密集），cook/DDC/glTF 是离线工具面；且 RFC-0020 §4.4 禁任意构建脚本的供应链纪律要求资产管线与 `rurix-pkg` 的 manifest/lock/vendor 红线同族，独立成 crate 责任边界最清晰。
- **`rurix-geom-pages` 不复用 `rurix_render::ClusterRecord` 类型**：页内 record 编码由 AP-PAGE-* 条款独立冻结（RFC-0020 §4.9 "不得依赖 Rust/C++ 原生 struct padding"），本来就必须手写 LE 字节编码；类型解耦同时消除依赖环。ClusterDag→页 record 的转换器放 `rurix-asset`。

### 1.2 Cook CLI = 独立 bin `rxcook`，不做 `rx` 子命令

`rx` CLI 子命令面（build/check/run/fmt/bench/vendor/test）属 **RXS-0180 stable API 快照冻结面**（步骤 49 的 `stable_api.snapshot` 含 "rx CLI 子命令面"）。给 `rx` 加 `cook` 子命令 = 触碰 stable 面，需快照更新与额外治理成本，且资产 cook 是引擎工具而非语言工具链。裁决：`src/rurix-asset` 内 `[[bin]] name = "rxcook"`，子命令形态：

```text
rxcook build   --manifest <cook.toml> --out <root> --ddc <dir>   # 全 DAG 构建
rxcook import-gltf / cook-texture / build-geom-pages ...          # 单节点调试入口
rxcook decode-page --disk <p.rxpd> --emit-digest                  # smoke 的 CPU 参照口
rxcook verify --double-build ...                                  # M79 双构建 verifier
```

声明文件沿 `rurix-pkg::toml` 手写 TOML parser 复用（RFC-0020 §3 的示意语法即 TOML 形态），不引 serde。

### 1.3 依赖策略三项裁决（用户点名疑点）

| 疑点 | 裁决 | 论证 |
|---|---|---|
| glTF 解析 | **手写严格 JSON parser + glTF 语义层，零第三方** | serde_json 不在树；仓库有手写 TOML/PPM/SPIR-V/DXIL 编解码先例；M81 判据要求 fail-closed 严格性（重复 key、越界、未知扩展全拒），第三方宽容 parser 反而要"再收紧"，手写 strict parser 是判据的直接实现。JSON 子集（glTF 用面）解析器约 600~800 行，量级低于仓内 dxil_sig_gate |
| KTX2/Basis 转码 | **vendor `basis_universal`（Apache-2.0）经 `rurix-basis-sys`（cc 构建，非 cmake）**；tolerance 验证用**自写 BCn 解码器**独立对拍 | M83 判据字面"真实 codec（非占位）"——手写真实 BC7/ASTC/Basis **编码器**是 XL×3 不现实；basis_universal 单 vendor 同时覆盖 KTX2 容器、Basis(UASTC)、→BCn/ASTC 转码四条格式腿。物理 vendor 先例在树。解码验证独立手写（BC1/4/5/7 解码是编码复杂度的 ~1/10），避免"vendor 自证" |
| 压缩/解压 | **自定义 `RXPZ-LZ1`（手写字节向 LZ77，LZ4-block 风格）**；GDeflate 不做 | M38 无 symbolic gate（P1 未 go），GDeflate 兼容不被任何判据要求；M04 只要求"压缩流确定性 + 未知 codec fail-closed"，codec 本身自选。零依赖手写 LZ1（贪心最长匹配 + 固定 hash 链遍历序 → 确定性）约 300 行，解码天然适合未来 GPU 化（字节向无熵编码）。zstd/flate2 不在树，引入即破坏供应链纪律。CPU-only 解压首期成立：M37 判据只要求"解压"环节真实存在于链上，GPU 解压属 M38/G8.7 判档 |

## 3. G8.3 各门设计

### 3.1 M79 `g8.p0.m79.asset_determinism`

**实现方案**（`src/rurix-asset`）：

- `canon.rs`——**手写 deterministic CBOR 冻结子集**（RFC-0020 §4.2 七条规则逐条实现）：
  - map key 仅非负整数 field-ID，按最短编码字节序排序，重复即 `Err`；整数最短编码；禁 indefinite-length；语义无序集合按元素 canonical bytes 排序、拒重复；
  - **首版收窄两刀（兑现评审 F17 硬前置且绕开其风险）**：① 核心 schema 禁浮点，recipe 参数首版只开放 int/enum/string/bytes——AP-CANON 条款字面登记"浮点字段未开放，开放前须条款修订并同时钉 NaN 归一规则"；② 用户字符串首版限 **ASCII 可打印子集**，非 ASCII fail-closed——条款字面登记"Unicode/NFC 面未开放"（NFC 对 ASCII 恒等，Unicode 版本钉死问题整体后移到真需要时）。
  - 对象 envelope：`magic "RXAP" | schema_id u32 | major u16 | minor u16 | canonicalizer_version u32 | payload_len u64 | schema_digest 32B | payload_digest 32B`（全 LE）。
- `schema.rs`——`SourceAsset / ImportRecipe / CookProfile / DerivedArtifact / ToolManifest / BuildManifest` 六对象，字段集合 = RFC-0020 §4.1 表逐字；`logical_uri` 校验（禁绝对路径/反斜杠/`.`/`..`/NUL）；未知 major/未知 required field fail-closed。
- `graph.rs`——声明式工具 DAG：节点 = `tool_id + tool_digest + typed_inputs + typed_outputs + canonical_params`，无环校验，稳定 ID 调度（调度序不进输出），环境变量清空，禁 shell 节点类型（类型系统上根本不存在该变体）。
- `verify.rs` + `rxcook verify --double-build`——两个隔离 tempdir（**不同绝对路径、空 DDC**），同一 manifest 各构建一次，比较 canonical DAG bytes、逐 artifact payload、顶层 BuildManifest digest；再做四类单变量变更（依赖内容 / recipe 参数 / profile 字段 / tool version）各一次，断言受影响节点 key 变化 + **无关节点 key 不变**。
- 首批固定工具集（M79 smoke 的 DAG 用真工具，非占位）：`rurix.gltf.import.v1`（M81）+ `rurix.geom.pages.v1`（M01）+ `rurix.texture.cook.v1`（M83，若未落则首批 DAG 用前两者，M83 落地后追加语料）——因此 **M79 的 smoke 合入排在 M81/M01 之后**（见 §5 顺序）。

**spec 条款草案要点**（`spec/asset_pipeline.md`，对应 AP-SCHEMA + AP-CANON + AP-GRAPH）：

1. AP-SCHEMA：六对象字段闭集 + 版本/未知字段拒录律 + logical_uri 语法；
2. AP-CANON：CBOR 子集七规则 + envelope 布局字面（逐字段偏移/宽度）+ ASCII/浮点收窄登记 + canonicalizer_version 进 schema digest；
3. AP-GRAPH：节点五元组、无环、无脚本边界（shell/`build.rs`/网络非节点类型）、env 清空白名单律、GPU encoder 不产签名 artifact（G8.3 全程）。

**RED 语料**（`conformance/asset/canon/{accept,reject}` + `conformance/asset/graph/reject`）：

- accept：六对象各一最小实例的 canonical bytes golden（checked-in 字节）；
- reject：duplicate-field-id、非最短整数编码、indefinite-length、unknown-major、unknown-required-field、非 ASCII 字符串、绝对路径 URI、`..` 段、DAG 环、未注册 tool、未声明 env 引用（各一件，共 ~11 件）。

**smoke `ci/g8_asset_determinism_smoke.py` 的 `checks.*`**：

```text
canon_golden_byte_equal            六对象 canonical bytes == checked-in golden
canon_reject_corpus_fail_closed    reject 语料全拒且错误类别匹配
double_build_isolated_roots        两根路径不同 + 起始 DDC 为空（防暖缓存假双构建）
```

### 3.2 M80 `g8.p0.m80.ddc_content_address`

**实现方案**（`rurix-asset::ddc`）：

- **key**：RFC-0020 §4.3 九段 preimage 逐字实现——`SHA-256("rurix-ddc-artifact-v1\0" || (len_u64_le || canonical(seg)) × 9)`，段序固定：source_set / dependency_keys / import_recipe / cook_profile / tool_chain / schema_set / abi_set / artifact_kind / output_id（页类 output_id 含 `logical_page_id`）。
- **CAS 布局**：

```text
<ddc_root>/objects/<aa>/<64hex>     aa = key 前两 hex；文件内容 = artifact payload 原字节
<ddc_root>/meta/<aa>/<64hex>.rxap   DerivedArtifact metadata（canonical envelope）
<ddc_root>/tmp/<pid>_<seq>          同卷临时文件；写全 + flush 后原子 rename
```

- get：读出后复核 `byte_len` + SHA-256(payload) == metadata 记载；不符 → `Miss{Corruption}` 诊断（不删对象、报告路径，交上层处置），**绝不返回脏对象**。put：目标已存在 → 逐字节比对，不同 payload = hard error（`Err(KeyCollision)`）。eviction = 删除 objects/meta 对，随后可从空 DDC 重建（M79 verifier 复用）。
- Windows 原子性：`std::fs::rename` 同卷 NTFS 语义 + 先写 tmp；并发同 key put 用 rename 的"已存在则比对"路径兜底。

**spec 条款要点**（AP-DDC）：九段 preimage 布局字面（域分隔符/长度前缀 u64 LE）、immutable CAS 语义（同 key 异 payload = hard error）、get 复核律、原子落盘律、eviction/rebuild 语义。

**RED 语料**（`conformance/asset/ddc/`）：九段各一的 mutation 向量表（checked-in JSON：base preimage + 九个单段变体 + 期望"key 必变"）；损坏对象三件（位翻转 / 截断 / 长度字段不符）。

**smoke `checks.*`**：

```text
preimage_covers_source_digest        preimage 重建含源 digest（结构性断言）
preimage_covers_dependency_keys      同上，依赖段
preimage_covers_tool_version         同上，tool_chain 段
preimage_covers_cook_profile         同上，profile 段
same_preimage_same_key               相同 preimage 两次计算同 key
put_get_byte_equal                   put→get 逐字节相等
mutation_source_flips_key            ┐
mutation_dependency_flips_key        │
mutation_recipe_flips_key            │
mutation_profile_flips_key           ├ 九段各一次单变量 mutation（RFC §4.5 评审 F6：
mutation_toolchain_flips_key         │ MAP 的"四类"是下限，九段全覆盖）
mutation_schema_set_flips_key        │
mutation_abi_set_flips_key           │
mutation_artifact_kind_flips_key     │
mutation_output_id_flips_key         ┘
bitflip_rejected_as_corruption       位翻转 get → 拒绝 + corruption 诊断，不命中
truncation_rejected                  截断 → 拒绝
concurrent_same_key_put_safe         并发同 key put（两线程）→ 单对象、字节一致
evict_then_rebuild_key_stable        驱逐后重建 → 同 key 同字节
```

device `not_applicable`。counter：`g8.counter.ddc_content_address_legs >= 19`。

**依赖**：M79 的 canonicalizer（同 crate 内，紧随 M79 合入或同 PR 拆两 gate 两 PR——推荐两 PR，独立绿）。**风险**：preimage 漏输入（改 tool 仍命中）——止损即九段 mutation 语料。**工作量：M**。

### 3.3 M81 `g8.p0.m81.gltf_import`

**实现方案**（`rurix-asset::gltf`）：

- `json.rs`：手写严格 JSON parser——拒重复 key、拒非法 UTF-8/裸控制字符、数字溢出显式 `Err`、深度上限、**保留对象内 key 出现序**（canonical 表排序由语义层做，不由 parser 吞）。

### 3.5 M04 `g8.p0.m04.page_format_abi`

**实现方案**（`rurix-geom-pages::{disk,memory,codec}`）：

- **内存页 ABI（`RXPM`）**：device decoder 消费面——header（独立 magic `RXPM`、format_id、major/minor、section 表）+ 段：quantized position records（u16×3 + pad u16，16B 对齐）、index 段（u8 页内局部索引，4B 对齐）、cluster meta 段（定宽 u32 字段组）、量化参数段（f32 按位）。**所有 offset/alignment/element width 由 AP-PAGE-MEM 冻结**；禁 host struct memcpy——encode/decode 全手写 LE（RXGB 先例）。
- **磁盘页 ABI（`RXPD`）**：envelope = `magic "RXPD" | format_id | major u16 | minor u16 | endian u8 | header_size | section_dir_count | codec_id u32 | codec_version u32 | uncompressed_size u64 | compressed_size u64 | logical_page_id u64 | schema_digest 32B | payload_checksum 32B(sha256 of compressed bytes) | dependency_digest 32B`；payload = RXPZ-LZ1(内存页 image)。section 目录按 kind 排序、偏移/对齐全校验、空洞恒 0。
- **codec `RXPZ-LZ1`**（codec_id=1）：字节向 LZ77（64KB 窗口，token = 字面串长 + 匹配长 + 2B 偏移），编码器贪心最长匹配 + hash 链固定遍历序 → 同输入同输出；解码零分配越界全查。
- **disk→memory 版本映射表**：`{(RXPD, major=1) → (RXPM, major=1)}` 常量表随 AP-PAGE-MEM 冻结（评审 F8：属 G8.3 冻结面）；decoder 流程 = envelope 校验 → checksum 校验 → 解压 → RXPM envelope/section 校验 → 交付。未列组合 → 拒。
- **device 解码腿（判据原文裁决）**：判据 = "device 解码 ABI 对同一页的 readback digest 等于 CPU 解码 digest"。裁决为**真 device 解码 kernel，不是上传后 memcpy readback**（后者不证明"解码 ABI"）。设计：
  - `.rx` compute kernel `geom_page_decode.rx`（单源纪律：rurixc → SPIR-V，禁手写 SPIR-V/Rust 替身）：输入 = RXPM image（storage buffer），kernel **结构性解包**——遍历 section 表、按冻结 offset/stride 展开每 cluster 的 records 到输出 SSB（展开流 = `(cluster_id, qx,qy,qz, index 三元组…, meta 字段…)` 全 u32 整数域；**f32 量化参数按位搬运、kernel 内零浮点运算**——刻意设计成整数域，消除 device/host FMA/rounding 位差风险，使 digest 可逐位判等）；
  - CPU 参照 = `rxcook decode-page --emit-expanded-digest`（同一展开律的 host 实现）；
  - device harness：`rurix-rt` 新 bin `vk_geom_page_decode.rs`（先例 `vk_ray_query.rs` 消费 smoke 编译的 .spv），host-visible 输入 buffer + dispatch + readback 展开流 → smoke 侧 SHA-256 与 CPU digest 比对；`RURIX_REQUIRE_REAL=1`、validation=0 进 checks。rurix-rt 不需依赖 rurix-geom-pages（digest 对比在 smoke 层，零新 crate 边）。

**spec 条款要点**（AP-PAGE-DISK + AP-PAGE-MEM）：两 ABI 的 magic/format_id/major 字面值一次冻结 + 逐字段偏移宽度表 + byte golden 同 PR；codec_id 注册表（1=RXPZ-LZ1）与 codec 流格式；四类拒录律（截断/checksum/未知 codec/未知版本）+ section overlap/OOB；disk→memory 映射表；device 展开律（输出流字段序 = 条款字面）；"G8.3 冻结、G8.4 只消费、变更走新 major"红线。

**RED 语料**（`conformance/geom_pages/reject/`，在 M01 基础上加）：`truncated_payload.rxpd`、`checksum_flip.rxpd`、`unknown_codec.rxpd`（codec_id=99）、`unknown_major.rxpd`、`section_overlap.rxpm`、`section_oob.rxpm`。golden：`tests/geom_pages/golden/` 下 2~3 页 checked-in .rxpd（uv_sphere 产物，合计 <40KB）+ 解码 records digest + 压缩流 digest。

**smoke `checks.*`**：


### 4.1 M37 `g8.p0.m37.streaming_io`

**实现方案**：

- **异步 I/O 线程模型（裁决：std::fs + 固定线程池，不用 IOCP）**：`rurix-asset` 不参与；新模块归 harness 侧（见下）。`StreamIoPool`：固定 2 工作线程 + `mpsc` 请求/完成队列；请求 = `(page_id, file_offset, len)`；工作线程 `File::read_exact_at`（Windows `seek_read`）读真实临时文件。**论证不用 IOCP/overlapped**：判据要求"真实磁盘 async read（不得预载内存替代）"——相对消费者异步的真实文件读即满足字面；IOCP 引入新 unsafe 面（HANDLE/OVERLAPPED FFI）与 Windows-only 复杂度，而本门判绿点在链条完整性与迟到页语义，不在 I/O 吞吐（性能属 evidence 不判绿）。IOCP 留作 M38/GPU 解压判档时一并评估。
- **链条**：smoke 先用 `rxcook` 产 RXPD 页文件写入 temp 目录（真实落盘 + fsync）→ 帧循环：`FeedbackBuilder` 产请求 → `StreamingEngine::tick`（三预算，既有 host 面 0-byte 复用）→ 未驻留页派发 `StreamIoPool` → 完成的原始字节走 **decompress**（`rurix-geom-pages` RXPD decoder，含 checksum/版本校验）→ **upload**（见下）→ **GPU consume**。
- **upload/consume device 腿**：uc06-renderer 新增 `--stream-io` 模式（先例：`--w3-effects`/`--g75-residuals`/`--device-frame` 全走 uc06；uc06 已桥 rurix-render + rurix-rt + vulkan feature，新增依赖 `rurix-geom-pages` 一条边）。upload = render_exec 既有帧协议的 buffer 上传路（host-visible memcpy + generation bump）——**首波不加 staging→device-local 拷贝**：host-visible 即真实 device 可见内存，判据无 device-local 要求；若评审认为需要 staged copy，作为 render_exec 加性扩展复用 U32 审计边界（备选项，+M 工作量）。consume = `.rx` compute kernel `stream_consume_digest.rx`：对页 buffer 做单 workgroup 顺序 FNV-1a（u32 整数域）→ 结果 SSB readback；host 对 golden 解压页算同一 FNV 比对。
- **timeline 事件 provenance 格式**（evidence 内嵌）：`events:[{page,stage:"read|decompress|upload|consume",seq,t_ns}]`——`t_ns` 取 host 单调钟；upload/consume 完成点 = 该帧 fence wait 返回后打点。单页四阶段完成值**严格单调**断言逐页执行。
- **迟到页注入（故障注入开关）**：`StreamIoPool` 包一层 `FaultInjector{delay_ticks: Map<page, u32>}`——按 tick 计数（非墙钟）扣押指定页完成事件 → 确定性可复现。被扣押期间引擎按既有语义继续（页不驻留）；**确定性 fallback** = root 页钉住保证的粗粒内容（消费方在页未驻留帧消费 root/占位内容并记录该帧 fallback digest）；页到达后帧内容翻正确 digest。断言"至少一帧命中 fallback + 到达后转正确"。
- **queue_mode 诚实登记**：evidence 顶层 `queue_mode:"single"`（裁决见 §4.3），不声称跨队列。

**spec 条款**：M37 属运行时行为门，语义已由 RFC-0019 §4.8.3 + RFC-0020 冻结面覆盖，**预计零新 RXS**（库面行为走 evidence/schema 锚，镜像 G5/G6 "库不进语言"先例）；若评审要求流送时序义务成文，落 `spec/rendering_platform.md` 加性一条（+1 RXS 预算）。

**smoke `checks.*`**（`ci/g8_streaming_io_smoke.py`，REQUIRE_REAL）：

```text
real_disk_file_read              temp 文件真实存在 + 读字节计量 == 文件尺寸（防内存预载替身）
per_page_stage_order_monotonic   每页 read<decompress<upload<consume 完成值严格单调
```

### 4.2 门-GeomPage（独立 gate）

**治理形态裁决**：GeomPage 不在 21 个 symbolic key 内，但 `G-G8-6`/`g8.wave.4.exit` 要求"GeomPage 必过 + 独立 evidence"。方案 A（推荐）：独立脚本 `ci/g8_geom_page_gate.py` + 独立 schema `milestones/g8/g8_gate_geom_page_evidence_schema.json` + key `g8.gate.geom_page`（**避开 `g8.p{0,1}.m##` 命名空间**，不触 `check_g8_acceptance_map.py` 的 21 行集合断言）+ `CI_GATES.md` §5 加性增行 + 独立 numeric step；`g8_wave4_exit_check.py` 消费其 evidence。方案 B（并入 M37 smoke 第二 `--gate`）被否：稀释 M37 判据、且"独立 evidence"字面偏向独立文件。**范围红线**：本门只做"meshlet page streamer 消费冻结 M04 ABI + 按需驻留 + 迟到页"，**不承接 RD-039/M44 超显存 P4 字面**（父页 fallback 链/超显存场景留 G8.7，不为 RD-039 记任何 closed）。

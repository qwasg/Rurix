## 2. 重判口径说明（基于 G10.5 measured 事实）

1. **一锚重判 go、九锚维持 defer**：M99-clipmap 为唯一命中行——法定通道（G10.5 A/B 差距清单）的 R4（P0，GI = 屏幕探针单反弹，bistro HDR p90 delta=4.697253086805343 measured）与 C1（P1，GI/天光遮蔽口径差 = 室内亮度主差 ≈21× measured）双行实证「屏幕探针远场缺失成为画质 measured 问题」；按只追加程序重判 go，指定 **G11 画质修复期**为承接波次（G10 零实现面——重判 go 只指承接不实现，G11 只消费 G10.8b 锁定清单 R4/C1 行 + 承接锚）。其余九锚重判条件均未命中，承接锚字面 0-byte 维持（G9_P2_DECISIONS §3 原文逐字）。
2. **三锚触发评估专项核验结论**：① M99-clipmap 命中（见上）；② M100-high 未命中——语料多灯场景真实存在（bistro 4+ 点光源 + emissive，R3 P0 measured），但 A/B 臂为 host CPU 参考管线、未消费 G9 低档 MegaLights GPU 管线，「低档在多灯 workload 下不足」measured 对照证据未产出，且 4+ 灯非海量灯 workload；③ M98-l4 未命中——G10.5 语料为双小场景闭集，无大世界 HLOD 运行时接口面就绪度证据，L4 计数可测面未建。
3. **承接锚字面 0-byte**：九行 maintain-defer 的「承接锚字面（重判后）」列与「原承接锚字面」列逐字相等（机器核验）；M99-clipmap 行为重判后新锚（含 G11+ 承接波次字面），原锚字面在「原承接锚字面」列 0-byte 存档。
4. **deferred.json 登记范围**：仅 RD 条目承载 history——M61（RD-039）、M52/M99-clipmap/M100-high（RD-040）四行落 history 只追加（2026-08-15 G10.6 重评窗行）；SAFE-GPU/M127/M98-l4/M114-strand/M118-hdr-cal/M125-adopt3 六行无 RD 条目归属**不新设 RD**（沿 G9.7 先例），留痕位置 = 本表 + G10_P2_DECISIONS.md 行。RD-039/040 总体 status 维持 open，id/title/reason/backfill_condition 四字段 0-byte，禁静默改判。
5. **no-go/defer 纪律**：九锚 defer 如实保持 open，不写进全绿叙述、不阻塞 G10.8a soak；每行承接锚「重判条件 + 兜底」齐备（§1 表 + [G10_P2_DECISIONS.md](G10_P2_DECISIONS.md) §3 承接锚清单）。

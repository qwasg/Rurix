> 本项目现状假设：rurix 需要补齐时域重建链——TAA/TAAU、TSR 类时域超分、时空重建、降噪器，以及它们的公共输入：motion vectors、reactive mask、历史验证。报告 2–4 已经为低采样信号（GI、RT 阴影/AO）预留了时域滤波需求，报告 4 确定 NRD（ReLAX/ReBLUR）为降噪接入件[^148^]。本报告回答：哪些自研、哪些接 SDK、公共底座怎么建、分阶段路线与验证方法。

## 结论摘要（TL;DR）

时域方向的三层金字塔，自研与集成的边界非常清晰。**底层（必须自研，一次投资处处受益）**：完整 motion vectors（几何+蒙皮+动态材质）、历史缓冲的外部资源化管理、深度/法线历史验证与 disocclusion 检测——这是 TAA、TSR 类超分、报告 2/3/4 所有时域滤波的公共底座，没有它每个效果都会各写一遍半吊子重投影。**中层（自研，有完整公开参照）**：TSR 类时域超分——Epic 已明确 TAA/TAAU 冻结不再演进、TSR 是唯一活跃主线且平台无关（SM5+ 即可），官方文档公开了全部 CVar 体系（历史 R11G11B10 选项、历史可 200% 超采样、闪烁时域分析、Resurrection 收敛加速、拒绝抗锯齿子质量档）[^262^][^257^]，官方数据 1080p 重建 4K 帧时间 57.5→33.37ms[^267^]。**顶层（接 SDK，绝不自研）**：ML 超分与帧生成——DLSS 4 的 transformer 模型（取代 CNN，时域稳定性/鬼影/运动细节全面提升）[^250^][^259^]、FSR 4 的 ML 化、XeSS 2/3 的 FG/MFG，这些是厂商用超算训练出来的资产；rurix 的入口是 DirectSR 统一 API（一次集成、运行时按硬件选择、Agility SDK 1.714+ 内嵌 DLSS SR 与 XeSS、后续加入 FSR 3.1）[^255^][^265^]，外加 FSR 3.1 开源（MIT、无 ML 硬件要求、含 Vulkan 后端）作为兜底与实现参照[^282^][^269^]。

### 1.2 清单的读法

2022–2026 时域方向的分水岭是**"手写时域重建"与"ML 重建"正式分家**：Epic 把 TAA 冻结、把全部精力押在手工设计的 TSR 上并公开其完整旋钮体系[^262^][^257^]；NVIDIA/AMD/Intel 则把质量竞赛搬进神经网络（DLSS 4 transformer、FSR 4 ML、XeSS 2/3），并用 DirectSR 把集成成本打到接近零[^250^][^255^]。对 rurix 的推论：**手写时域重建没有过时——它是 vendor SDK 的输入要求**（MV、深度、reactive mask 一个都不能少），也是 SDK 不可用平台（Linux/Vulkan 非主流场景）的保底；而 ML 部分一行都不该自己训练。另一条线索是**帧生成（FG/MFG）与超分的彻底解耦**：FSR 3.1 的 Frame Generation Prepare 与 XeSS-FG 的双候选机制都证明 FG 是独立可插拔层[^282^][^276^]——rurix 把 FG 归入 P3+ 评估，且以延迟测量为硬门槛。

## 2. 逐项分析：问题、算法、实现代价与工程复杂度

### 2.1 公共底座——motion vectors、历史验证与 disocclusion

**要解决的问题。** 一切时域技术的数学前提相同：把历史帧颜色按逐像素速度场重投影到当前帧，然后判断这份历史"信不信"。不信的场景有三类：遮挡揭开（disocclusion，历史里根本没有这个新暴露的表面）、着色变化（灯动、材质动、透明效应）、以及 MV 本身说谎（反射/折射/粒子/UI 的运动向量不可靠——DLSS 4 的技术页把"游戏引擎给的 MV 与深度在反射、高光、UI 上不准确"列为帧生成特有的难题，其解法是教网络在可靠处用、不可靠处补[^259^]）。手写体系的对应物是历史验证三件套：**深度/法线一致性测试**（重投影像素的深度与当前帧深度足够接近才接受）、**邻域裁剪**（variance/AABB clipping，把历史色钳制到当前帧 3×3 邻域的色域内，鬼影的直接克星）、**反应度掩码**（reactive mask，标记透明/粒子等"历史不可信"区域并降低其历史权重）。

**实现代价与 rurix 规格。** 底座工程量约 2–3 周，但它是"正确性工程"：MV pass 必须覆盖几何、蒙皮（骨骼速度）、顶点动画/材质位移（WPO 类，报告 3 的植被风场教训表明缺了它时域系统会大面积失效）；历史颜色/深度/模板以**外部资源**身份进出帧图（报告 5 纪律：跨帧资源不 transient）；抖动采样序列（Halton）与相机 jitter 矩阵进全局 uniform。验收也是硬性的：静态相机+静态场景下累积收敛到与超采样参考一致；移动物体边缘鬼影有可数的上限。这层做完，TAA 只是它上面的一个薄 pass，TSR 类超分只是"输入分辨率 < 输出分辨率"的同一 pass，报告 2/3/4 的滤波器共享同一验证例程——NRD 的 ReLAX/ReBLUR 内部同样是"重投影+验证+时空滤波"结构[^148^][^108^]。

### 2.2 TAA→TAAU→TSR——Epic 公开的完整旋钮体系

**要解决的问题。** Epic 在 FAQ 里说得直白：TAA/TAAU 是上代主机约束下的产物，**不会再改进**；TSR 才是活跃主线[^262^]。TSR 的定位是"平台无关的时域超分器"：SM5 级 GPU 即可运行，用远低于原生的内部分辨率（低至 1080p 重建 4K）摊薄 Nanite 几何与 Lumen 的成本，官方同场景对比帧时间 57.50ms（原生 4K）→ 33.37ms（1080p 上采样），质量接近原生 4K[^267^]。管线位置上它在景深之后、之后的一切都被上采样[^267^]；shader 针对 PS5/XSX 架构专门优化[^267^]。

**可照抄的机制清单。** Epic 文档把 TSR 的可调面几乎全部公开，对自研者是现成的需求规格：(1) **历史缓冲**：可选 R11G11B10 格式省带宽且无严重色精度问题（`r.TSR.History.R11G11B10`），历史分辨率可独立于当前渲染超采样到 200%（`r.TSR.History.ScreenPercentage`）以保细节[^257^]；(2) **闪烁时域分析**：按目标帧率自动收缩闪烁判定期（`r.TSR.ShadingRejection.Flickering.FrameRateCap`/`.Period`），把"60Hz 下稳定、24Hz 下闪烁"的美术资产与帧率解耦——这是"按时间周期判闪烁"而非"按帧数判"的精巧设计[^257^]；(3) **Resurrection**（收敛加速）与独立的**拒绝抗锯齿质量档**（`r.TSR.RejectionAntiAliasingQuality`），以及按 scalability 组打包的整套 CVar 分档[^257^]；(4) **不做锐化**：TSR 团队明确以"匹配参考"为唯一目标，锐化留给 tonemapper 后的可选 pass（Fortnite 全平台全超分器统一 `r.Tonemapper.Sharpen=0.5`）[^262^]。rurix 的 P1 规格书可以直接按这四条写，不必重新发明旋钮。

### 2.3 reactive mask 与透明/粒子——FSR 3.1 的公开经验

**要解决的问题。** 透明表面、粒子、体积雾这类"颜色不由表面几何决定"的像素是时域重建的最大失败源：它们的 MV 要么不存在要么撒谎，直接参与历史累积就是拖影。reactive mask 的机制是：标记这些像素的"反应度"，时域重建在该区域降低历史权重、更多依赖当前帧（代价是噪点/锯齿回归，收益是无拖影）。FSR 3.1 的发布说明专门提到"改进了从 reactive mask 输入中排除项的质量"[^282^]，其 SDK 同时支持自动生成 reactive mask 与手工提供（透明合成纹理）两条通道。这也解释了为什么 reactive mask 是 vendor SDK 的**标准输入槽位**而非可选件——DLSS/FSR/XeSS 的集成接口里它与时域输入同列。

**实现代价与 rurix 规格。** 两条通道都做：自动通道在透明/粒子 pass 渲染时顺带写出反应度（一个 R8 UNorm render target 的附加输出）；手工通道留给美术标记"此材质永不累积"（如全息特效、屏幕空间 UI 元素）。与 2.1 的验证逻辑合流：reactive mask 本质是先验的"历史可信度图"，与深度/法线测试的后验结果取并集。验收场景要包含"透明玻璃后的运动物体"与"粒子云穿行"两条回归脚本。

### 2.4 vendor 谱系 2025–2026——ML 重建、统一 API 与帧生成分层

**要解决的问题与格局。** ML 侧：DLSS 4 用 transformer 全面取代 CNN（SR/RR/DLAA 三件套），官方口径是时域稳定性、鬼影、运动细节、抗锯齿全面提升，且全 RTX 卡可用（MFG 才是 50 系专属）；DLSS 4.5 已上二代 transformer[^250^][^266^][^259^]。FSR 4 转向 ML 超分但保持跨厂商可用[^251^]。XeSS 2 把 SR/FG/XeLL 打包并在 2.1 开放到一切 SM6.4 GPU（Intel 卡走 XMX，其他走 DP4a/compute），XeSS 3 再上 MFG 2x/3x/4x[^276^][^272^][^279^]。集成侧：DirectSR 给出统一答案——不是超分器而是公共框架，Agility SDK 1.714 预览起支持运行时按硬件在 DLSS SR（驱动 560.38+ 内嵌）/XeSS/FSR 3.1 间切换，开发者不需要再捆各家 SDK[^255^][^265^]。社区格局分析的一致结论是：2025 年 DLSS 4 质量领先（尤其 RT 重场景）、FSR 4 跨厂商价值最高、DirectSR 是集成成本最低点[^251^][^253^]。

**rurix 的接口设计。** 仿 UE 的 `ITemporalUpscaler` 思路（UE 5.3 修复了第三方超分器热切换的崩溃问题，说明该接口的边界已经稳定[^262^]）：定义 rurix 自己的时域超分后端接口（输入：颜色/深度/MV/reactive mask/曝光；输出：目标分辨率颜色），三个实现——自研 TSR 类（P1）、FSR 3.1 开源（Vulkan 后端现成、MIT 许可[^282^][^285^]）、DirectSR（Windows 商店场景）。**帧生成单独一层**：FSR 3.1 的 FG 已与 upscaler 解耦（Frame Generation Prepare 用超分前的 MV/深度自行准备输入）[^282^]，XeSS-FG 的机制更透明——MV 重投影候选 + AI 光流重投影候选（捕捉阴影/反射/粒子这些引擎 MV 覆盖不到的运动）+ 第二个 AI 模型混合，UI 最后合成[^276^]。FG 对 rurix 是 P3+：先要有稳定的 60+ FPS 基线（AMD 明确不建议低基线开 FG[^281^]），再以输入延迟测量为启用门槛。

### 2.5 降噪器——与超分共享验证逻辑的姊妹系统

**要解决的问题。** 报告 2/3/4 的 RT 信号（GI、阴影、AO、反射）都是 1spp 级输入，降噪器是它们的时域累积器。NRD（ReLAX 漫反射/ReBLUR 镜面的分信号设计）已在报告 4 定为接入件：硬件门槛只是 inline trace，集成是库级的[^148^]。关键认知是**降噪器与时域超分是同一数学结构的两个应用**：都是"重投影 → 历史验证 → 邻域统计 → 加权累积"，只是超分的输入是全色渲染、降噪的输入是分解的漫/镜信号且要做方差驱动的空间滤波[^108^]。RT 阴影的专项滤波（RTG1 课程的泊松盘空间滤波+时域累积）已在报告 3 覆盖[^104^]。

**实现代价与 rurix 规格。** P2 的动作：接 NRD，并让其复用 2.1 底座的 MV 与验证例程（NRD 需要的 MV/深度/法线输入与 TSR 完全同构）。验收走报告 4 定下的同结构对拍法：与离线路径追踪参考在固定脚本场景下比 SSIM 与异常像素率[^148^]。长线跟踪 DLSS Ray Reconstruction——它用 transformer 统一替代手调降噪器[^250^]，是"降噪也 ML 化"的风向标，但接入面仍是 vendor SDK，不改变自研边界。

### 2.6 学术谱系——重建质量的长线参考

学术工作为手写体系提供算法弹药。CVPR 2024 的 **Neural SR with Radiance Demodulation** 指出超分的一大误差源是材质纹理与光照在 LR 渲染中纠缠，其解法是先解调辐射（除以材质反照率）、在光照域做时域重建、再与 HR 材质合成——既保细节又抗锯齿，这一思想对手写 TSR 同样成立（光照/材质分离累积）[^290^]。AAAI 2024 的 **Low-latency Space-time Supersampling** 面向云游戏/VR 的延迟敏感场景，用 G-buffer 引导做外插式帧重建[^292^]；TOG 2025 的**移动轻量边缘感知超采样**给出 ×2 LUT 方案并坦承其抗锯齿边界（FSR 2 类方法同限）[^291^]；神经注视点超分则为 VR 提供了"按注视分配重建质量"的维度[^293^]。这些都不进 P0–P2 主线，但 radiance demodulation 的"分离累积"思想值得在 P3 质量攻坚时实验——它对闪烁抑制可能有实质帮助。

| 阶段 | 目标 | 关键工作 | 验收标准 |
|---|---|---|---|
| **P0 公共底座 + 自研 TAA** | 时域基建正确 | MV 三类速度全覆盖；历史外部资源化；重投影+深度/法线验证+邻域裁剪；Halton jitter | 静态场景收敛对齐超采样参考；验证层零错；回归脚本入库 |
| **P1 TSR 类时域超分 + reactive mask** | 低分辨渲染高分辨输出 | 输入/输出分辨率解耦；历史 R11G11B10 与超采样选项；闪烁时域分析（帧率解耦）；收敛加速；reactive mask 双通道 | 50–67% 内部分辨率下质量/帧时间对照表；透明/粒子回归通过 |
| **P2 降噪器接入 + vendor SDK 层** | RT 信号可用 + 开放生态 | NRD（ReLAX/ReBLUR）接入复用底座；upscale 后端接口三实现（自研/FSR 3.1/DirectSR） | 与离线参考 SSIM 门禁通过；三后端可运行时切换 |
| **P3 质量攻坚** | 逼近原生 | disocclusion/薄几何/高速运动回归集；radiance demodulation 式分离累积实验；锐化策略（tonemapper 后） | 与原生渲染的 SSIM/FLIP 门禁；Fortnite 式统一锐化参数 |
| **P3+ 帧生成评估** | 流畅度上限 | FG 独立层（参照 FSR 3.1 解耦与 XeSS-FG 双候选机制）；输入延迟测量 | 60+ FPS 基线达标且延迟增幅可接受才启用 |

![时域方向分阶段路线](images/r7_roadmap.svg)

与整体计划的咬合：P0 底座同时服务报告 2（GI 时域累积）、报告 3（VSM/SMRT 滤波）、报告 4（RT 降噪），应排在它们的 P1 之前或与报告 5 帧图 P0 同期（历史资源的外部化依赖帧图纪律）；P1 的超分是报告 1（Nanite 级几何密度）与报告 2（Lumen 级 GI）性能达标的放大器——Epic 的 57.5→33.37ms 对照正是"几何+GI 成本由超分买单"[^267^]；P2 的 NRD 与 DirectSR 分别衔接报告 4 的 RT 闭环与发布渠道需求。

## 5. 必须新增的数据结构、shader 阶段、资源布局与验证方法

**数据结构。** `HistoryBundle { color: ExternalTexture, depth: ExternalTexture, frame_id: u64 }`；`TemporalJitter { halton_index, proj_matrix_delta }`；`ValidationParams { depth_tolerance, normal_tolerance, clip_box_sigma }`；`ReactiveMaskParams { auto_rt: R8, manual_override: Texture? }`；`UpscaleBackend` trait（`fn dispatch(inputs: TemporalInputs, output: &mut Texture)`，三实现）；收敛/命中率统计计数器（`stat TSR` 类）。

**shader 阶段。** 新增三个 pass：(1) **MV pass**（随主几何 pass 的 MRT 输出：屏幕空间速度 RG16F，蒙皮与 WPO 同通道累加）；(2) **时域重建 compute**（重投影+验证+邻域裁剪+累积+可选分离累积，自研 TAA 与 TSR 类超分共用一个 kernel、仅分辨率映射不同）；(3) **reactive mask 合成**（透明/粒子 pass 的 R8 附加输出）。修改：相机 jitter 进投影矩阵；vendor SDK dispatch 作为帧图的一个外部 pass（DirectSR/FSR 各持一份资源描述）。

**资源布局。** 历史颜色可选 **R11G11B10**（带宽省且无严重色精度问题，UE 默认开启同款选项[^257^]）或 RGBA16F（高质量档）；历史分辨率可独立于渲染分辨率超采样（最高 200%[^257^]）；历史深度 R32F；MV RG16F；reactive mask R8。全部历史资源以帧图外部资源身份持有，双缓冲轮换。

**验证方法。** 四类。**收敛正确性**：静态相机静态场景下 N 帧后与超采样参考逐像素对齐（SSIM ≥ 阈值）——这是 TSR 团队"匹配参考"口径的可执行版本[^262^]。**伪影回归集**：disocclusion 揭幕、薄几何/栅栏、高速运动、透明后运动、粒子云、植被风场（WPO MV 用例）六条固定脚本，逐帧 FLIP/SSIM 双指标+鬼影像素计数。**性能对照**：每个内部分辨率档（50%/58%/67%/100%）输出帧时间与质量对照表，对齐 Epic 公布的对照方法[^267^]。**收敛率观测**：`stat TSR` 类的 feed/收敛率统计进 HUD，帧率低于阈值时闪烁抑制参数自动收缩的行为也要被脚本断言[^257^]。

## 6. 风险与缓解

**最大风险是底座不完整导致"每个效果各自打补丁"**：MV 缺蒙皮或 WPO 速度，TAA 看起来"基本可用"，但 GI 滤波与降噪器会在角色与植被上持续翻车——报告 3 的 VSM 失效分析已经证明植被风场是重灾区。缓解：P0 验收把"MV 覆盖三类速度源"列为硬性条目，回归集里角色与植被用例不过不得进 P1。**其次是 vendor SDK 的平台分裂**：DirectSR 只覆盖 Windows 商店/桌面 D3D12，Vulkan/Linux 与自助分发要靠 FSR 3.1 开源与自研后端[^255^][^282^]——三实现接口（P2）就是为这条分裂准备的，自研 TSR 类后端在任何平台上都是保底，不存在"没 SDK 就没超分"的死角。

**闪烁与帧率耦合**是第三个坑：美术资产在 60Hz 稳定、24Hz 闪烁是物理必然，Epic 的解法是按时长（而非帧数）判定闪烁并把判定期与目标帧率绑定[^257^]——rurix 应直接照抄 `FrameRateCap`/`Period` 语义，不要发明自己的阈值。**帧生成的延迟与基线陷阱**最后强调：FG/MFG 在低基线帧率下同时放大延迟与伪影（AMD 明确不建议低配硬件开 FG[^281^]，社区实测 30→60 的体验不佳），且 UI 需要单独的合成路径（XeSS-FG 提供重复 UI 与重渲染 UI 两种选项[^276^]）；P3+ 的启用门槛（60+ FPS 基线 + 延迟测量 + UI 合成方案）一条都不能少。ML 超分本身不做自研这条边界再钉一次：DLSS 4 transformer 是超算训练资产[^250^]，rurix 的竞争力在底座质量——MV 与历史验证做得越好，vendor SDK 的输出就越好，这是集成者唯一能控制的变量。

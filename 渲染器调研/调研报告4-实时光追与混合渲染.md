# 调研报告 4：实时光线追踪 / 混合渲染系统

> 面向 rurix（H:\rurix）的前沿论文与工业技术调研 · 2022–2026 · 出品日期：2026-07-28
>
> 本项目现状假设：已有实时/离线路径追踪基础与图形底座（render graph/RHI、Vulkan/DXIL），但 RT 相关能力不够稳定/完整；还没有成熟的混合 GI（报告 2）与多灯投影（报告 3/6）。本报告回答：技术清单、逐项（问题/算法/实现代价/工程复杂度）、适配选择、**最快形成"最小 RT 闭环"的路线**、以及需要补齐的底层能力。

---

## 结论摘要（TL;DR）

对"RT 不稳定"的 rurix，最快、风险最低的最小闭环**不是**建完整 DXR/Vulkan RT 管线（raygen pipeline+SBT+命中着色体系），而是 **`VK_KHR_ray_query` 计算着色器内联追踪**：只需要一份能正确构建/更新的 TLAS，就能在任意 compute pass 里发阴影/AO/反射光线，绕开全部 SBT 管理、shader record 布局与管线状态爆炸问题——NVIDIA 的 NRD-Sample 对硬件的唯一要求就是"支持 inline trace"[^148^]，RTXDI SDK 同样只要求 `KHR_ray_query` 或 `KHR_ray_tracing_pipeline` 二选一[^139^]，Vulkan 官方教程的 AO 示例正是"GBuffer+compute ray query"这一形态[^149^]。

在此闭环之上，技术演进分四步走：**P0 最小闭环（TLAS 加固 + ray query 硬阴影/AO 单效果 + 时域降噪）→ P1 效果扩展与 BVH 更新策略分级 → P2 按需在材质多样化处引入 RT pipeline/SBT（并与报告 2 的 GI 追踪层合流）→ P3 ReSTIR DI 多灯（直接以 RTXDI MinimalSample 为蓝本，其 RAB_ 桥接接口要求应用自持材质/场景/RT/GBuffer，与 rurix 的所有权边界完全吻合）[^138^][^147^]**。质量/性能长线是 ReSTIR PT Enhanced（I3D 2026 最佳论文，2-3× 提速、DI+GI 统一储层）[^142^]与 SER/OMM（Vulkan 已有正式扩展，黑神话悟空 ReSTIR GI 实测 3.7×、Alan Wake 2 实测降本 39%）[^127^][^135^]。

### 1.2 清单的读法

这份清单可以压成一句话：**"追踪硬件化、采样储层化、着色相干化"是 2022–2026 RT 的三条主线**。第一条主线（DXR 1.2/SER/OMM）回答"GPU 怎么跑 RT 更快"；第二条（ReSTIR 家族从 DI 到 PT Enhanced）回答"每帧 1 根光线怎么够"；第三条（RTXDI/RTXPT/NRD 的开源集成样板与黑神话等生产案例）回答"引擎怎么把它装进去"。rurix 的缺口在第三条的一半——加速结构生命周期管理与效果集成——因此本报告把"最小闭环"定义为：**TLAS 正确 + 一个 ray query 效果 + 一个降噪器**，其余全部后置。

## 2. 逐项分析：问题、算法、实现代价与工程复杂度

### 2.1 ray query vs RT pipeline/SBT——最小闭环的路径之争

**要解决的问题。** 把 RT 装进光栅引擎有两条 API 路径：**RT pipeline**（raygen/closest-hit/any-hit/miss/intersection 着色器+着色器绑定表 SBT）与 **ray query**（在任意着色器内联发起遍历）。前者表达力强（命中即着色、材质随几何分派），但引擎要管理 SBT 的记录布局、管线库编译、递归深度与负载内存，且 Vulkan 与 DXR 的 SBT 语义有实质差异——DXR 支持 local root signature 做逐记录资源绑定，Vulkan shader record 只允许常量，移植时绑定模型必须重设计[^152^]。后者把"追踪"降级为着色器里的一条指令：命中信息由调用者自己消费，材质求值、BRDF、写入目标全在本来就有的 compute/fragment 代码里[^149^]。

**实现代价与复杂度对比。** ray query 路径的新增表面只有一个：`accelerationStructureEXT` 描述符+`rayQueryEXT` 指令流，rurix 现有 RHI 只需加两类对象（AS 句柄、构建/更新命令）；NRD-Sample 把硬件门槛直接写成"任何支持 inline trace 的 GPU"[^148^]，RTXDI 也接受 ray query 作为等价后端[^139^]。RT pipeline 路径则是十倍级的工程量：SBT 分配与压缩、管线库与缓存、命中组与材质系统的映射、DXR/Vulkan 双后端语义差异[^152^]。**结论：P0–P1 用 ray query 覆盖阴影/AO/反射/GI 探针追踪（报告 2 的追踪层也是它），RT pipeline 推迟到"命中点需要多样化材质着色"真正出现时（P2，与 Lumen 类 GI 的 hit lighting 或路径追踪模式同步引入）。**

### 2.2 BLAS/TLAS 生命周期——RT 稳定性的真正所在地

**要解决的问题。** rurix"RT 不稳定"的最可能根源不在追踪本身，而在加速结构的资产管理：哪些几何进 BLAS、动态物体 refit 还是 rebuild、TLAS 每帧重建还是增量、实例增删时的 compaction。Khronos 以 Wolfenstein: Youngblood 为案例的最佳实践给出了基线答案：静态几何顶点压到 16 位整数、索引 16 位；多几何合 BLAS 以减实例数（命中组内以 `gl_GeometryIndexEXT` 区分）；蒙皮/动画物体经 compute 管线输出世界空间顶点再更新 BLAS；refit 用于变形、rebuild 用于顶点数变化的拓扑改变[^141^]。

**实现代价。** 这是纯工程量但决定成败：一个"AS 管理器"模块（约 2–3 周）——BLAS 构建缓存（按网格哈希复用）、动态 BLAS 的 refit 队列、TLAS 快速重建（实例数 <10k 时亚毫秒级）、以及紧凑化（compaction）策略。**它也是报告 1（Nanite 类几何的 RT 对应物是 RTX Mega Geometry/vk_lod_clusters 的簇级 BLAS）[^45^]、报告 2（GI 追踪层）、报告 3（MegaLights 式 RT 阴影）的公共底座**，投资一次、四处处受益。验证标准是硬性的：任意场景 TLAS 构建时间、动态物体运动时无漏光/无自交瑕疵、AS 显存占用有界。

### 2.3 ReSTIR DI / ReGIR / ReSTIR GI——多灯与间接光的采样革命

**要解决的问题。** 传统延迟渲染的成本随灯数线性增长，而"哪些灯重要"这件事本身就是逐像素的空间函数。ReSTIR DI 把灯光选择变成储层重采样：每个像素先从便宜分布（均匀/功率）抽若干候选灯，再用含几何/BRDF/可见性的贵分布选一盏，时域与空域邻居的储层互相复用，等效采样数成倍放大；ReGIR 在世界空间网格里预采样灯光，为次表面与 ReSTIR DI 提供初始分布（"ReGIR 喂 ReSTIR"是 RTXDI 样例默认模式）；ReSTIR GI 把同一思想推广到间接光[^138^]。

**实现代价与集成形态。** RTXDI 的集成哲学是"**应用拥有一切，SDK 只给采样数学**"：材质模型、场景表达、RT 实现、GBuffer 访问、图形 API 都由引擎提供，通过 `RAB_`（RTXDI-Application Bridge）回调桥接——这正好是 rurix 想要的边界，不会引入任何封闭二进制依赖[^138^]。帧序列是固定的：灯光预采样→（可选）ReGIR 构建→初始采样+时域/空域重采样→最终着色（含可见性光线）→降噪器置信输入→降噪[^138^]。SDK 自带 MinimalSample（单合并 pass 的最小可行集成）与 FullSample（标准多 pass），并有棋盘格渲染选项把光线预算减半[^147^][^144^]。对 rurix，这是 P3 的**直接施工图纸**，前提是 P0–P2 已备好三样输入：稳定的 TLAS、GBuffer 访问、材质 BRDF 回调。

### 2.4 SER 与 OMM——RT 的"免费"性能轨

**要解决的问题。** RT 成本的很大一块不是遍历而是**发散**：相邻像素命中不同材质、走不同代码路径，warp 活跃度跌到 20% 量级。SER 把遍历与着色解耦成 hit object——先 `hitObjectTraceRay` 拿命中，再 `reorderThread` 让 GPU 按着色器/数据局部性重排，最后 `hitObjectExecuteShader` 执行[^135^]。OMM 则把 alpha-test 几何的不透明度微缩编码进 BVH，省掉海量 any-hit 回调[^124^]。

**生产证据与代价。** 证据链已经很强：黑神话悟空的 ReSTIR GI 相干性仅 20.5%，开 SER 后 pass 从 15.10ms 降到 4.08ms（RTX 4070Ti 4K，3.7×，相干性升至 69.9%）；Alan Wake 2 在 3700 万光线/帧的密林场景用 SER+OMM 降本 39%；Indiana Jones 仅启用即 11%、配合 live state 优化达 24%[^127^]。SER 在 Vulkan 已是正式扩展（`VK_EXT_ray_tracing_invocation_reorder`，2025-11 发布[^127^]），D3D12 侧随 DXR 1.2/SM 6.9 落地（NVIDIA RTX 全系列支持，20/30 系重排为空操作但无副作用，可同代码覆盖）[^128^]。对 rurix：**这是 P2 引入 RT pipeline 时的同步项**（ray query 场景的收益有限），成本只是着色端改造+特性查询。

### 2.5 路径追踪模式与降噪——从"效果"到"画质模式"

**长线图景。** 当 P0–P3 齐备，rurix 就拥有了与 RTXPT 相同的组件集：ray query/RT pipeline 双后端、ReSTIR DI/GI、降噪链。ReSTIR PT Enhanced（I3D 2026 最佳论文）把这条线推到新高度：互惠邻居选择把空间复用成本减半、足迹判据让移位映射更鲁棒、重复图降低时空相关伪影、直接光与全局光统一储层——整体 2–3× 提速且误差下降[^142^]。RTXPT 开源仓库证明了这些组件可以集成进一个 DX12/Vulkan 双后端、glTF 资产、NRD ReLAX/ReBLUR 降噪的实时路径追踪器[^132^]。降噪侧，NRD 只需"inline trace"级硬件[^148^]，其 ReBLUR（漫反射）与 ReLAX（镜面/路径追踪信号）可直接挂到 rurix 的 ray query 效果之后，把 1spp 信号拉到可用——Cyberpunk RT:Overdrive 的"路径追踪+ReSTIR DI+NRD"组合就是这条路的生产范本[^134^]。

## 3. 适配 rurix 的选择推理与最小 RT 闭环路线

### 3.1 选择推理

rurix 的 RT 现状（"有路径追踪基础、RT 不稳定"）指向一个诊断：**缺的不是算法而是工程基座**——TLAS 生命周期、效果集成形态、验证方法。因此选择原则是"**最小表面积优先**"：ray query 先于 RT pipeline（2.1）、单效果先于效果矩阵（先硬阴影或 AO，它们的正确性最容易对拍）、自研时域滤波或 NRD 先于 ReSTIR（ReSTIR 的一切质量都建立在稳定的可见性查询上）。与报告 2 的接口要提前对齐：GI 追踪层与本报告的 ray query 封装必须是**同一份代码**，避免"GI 一套 RT、阴影一套 RT"的分裂——GI-1.0/SHaRC 的做法（追踪层输出统一为命中辐射度）就是范式[^83^][^81^]。

另一个关键决策是**双后端语义收敛**：rurix 是 Vulkan/DXIL 双后端，ray query 在两侧语义一致（`rayQueryEXT` ↔ DXR `RayQuery`），而 RT pipeline 两侧差异大（SBT/local root signature[^152^]）。这进一步压低 ray query 的相对成本，并把 RT pipeline 推到"只有 Vulkan+DXIL 都有余力时才做"的位置——好消息是 ReSTIR PT Enhanced 与 SER 都不强迫这个决定：前者可在 ray query 上实现（RTXDI 即如此[^139^]），后者在 Vulkan 侧已正式可用[^127^]。

### 3.2 最小 RT 闭环（P0 的完成态）

![最小 RT 闭环架构](images/r4_rt_closure.svg)

**闭环 = TLAS 管理器 + 一个 ray query 效果 pass + 时域/空间降噪 + 对拍验证。** 推荐首个效果二选一：**RT 硬阴影**（与报告 3 的 VSM/SMRT 对照验证，向光源一根光线，输出可见性缓冲）或 **RTAO**（GBuffer 法线半球余弦采样，Vulkan 官方教程即此形态[^149^]）。验收：与离线路径追踪器对拍（同一 TLAS、同一几何）、动态物体移动无漏光、1spp+降噪后 SSIM 达标、效果 pass <1ms@1080p（RT 硬阴影单光线在当代 RT 卡上远低于此）。

## 4. 需要补齐的底层能力

| 能力 | 现状缺口 | 补齐内容 | 阶段 |
|---|---|---|---|
| **RHI 加速结构抽象** | 无/不稳定 | AS 句柄、构建/更新命令、scratch 缓冲管理、compaction、特性查询（ray query/SER/OMM） | P0 |
| **BLAS 构建缓存与分级更新** | 无 | 静态：一次构建+compaction+16 位顶点；动态：refit 队列；拓扑变化：重建[^141^] | P0–P1 |
| **ray query 着色器工具链** | 无 | GLSL/HLSL `rayQueryEXT` 编译到 SPIR-V 与 DXIL 双路径、payload 布局规范 | P0 |
| **效果缓冲与降噪链** | 部分 | 可见性/AO/反射辐射度缓冲契约、运动矢量输入、时域滤波（自研 à-trous 或 NRD ReBLUR/ReLAX[^148^]） | P0–P1 |
| **GBuffer↔RT 的材质桥** | 无 | 命中点材质求值回调（ray query 内联）→未来的 RAB_ 桥接同形[^138^] | P1 |
| **SBT/管线库管理（可选）** | 无 | shader record 布局（Vulkan 常量限定[^152^]）、命中组映射、管线编译缓存 | P2 |
| **SER/OMM 特性路径** | 无 | 特性查询、hit object 着色模式、OMM 资产标记[^127^][^124^] | P2/P4 |
| **验证与画像** | 无 | 与离线路径追踪器的自动对拍（同 AS 同几何）、逐效果 GPU 计时、相干性度量（Nsight/RGP[^127^]）、AS 显存监控 | 全程 |

**验证方法的三个要点。** 其一，**同结构对拍**：光栅引擎与离线路径追踪器必须用同一份 TLAS/BLAS 输入做逐像素对比，否则"RT 不稳定"会永远在"几何错误"与"采样错误"之间甩锅——rurix 已有离线器，这是现成优势。其二，**动态序列回归**：漏光、自交、bias 伪影只在运动和变形中暴露，CI 里要有"蒙皮角色+移动灯+相机剪辑"的固定脚本场景，逐帧 SSIM 与异常像素计数双指标。其三，**相干性前置度量**：在 P2 评估 SER 之前先用 Nsight/RGP 的"active lanes/predicated-on threads"度量基线相干性[^127^]，避免在本来就不发散的 pass 上浪费改造。

## 5. 风险与缓解

**最大风险是"加速结构债"**：BLAS 全量重建掩盖更新策略缺失，在资产上量后突然爆炸。缓解：P0 就把 BLAS 缓存键（几何哈希）、refit/rebuild 决策树、compaction 时机写成显式策略并配监控[^141^]。**其次是范围蔓延**：RT pipeline/SBT 的诱惑会提前出现（材质化反射很诱人），但 SER 的生产数据表明它的收益场景是"多材质多弹跳着色的 GI/PT"[^127^]，在此之前投入回报低——本报告把 P2 标记为"按需"正是为此。**ReSTIR 的偏置风险**：时空复用引入的偏置在薄几何/高速运动下可见，RTXDI 的 Noise and Bias Guide 与置信通道是缓解手段[^138^]，且 PT Enhanced 的足迹判据与重复图进一步收敛了该问题[^142^]——但这一切都要求 P0 的可见性查询先稳定，再次印证"最小闭环先行"。

**跨报告协同风险**最后强调：报告 1（Nanite 类几何）若推进到 P3 之后，其 cluster 层级与 RT 的关系需要重新评估——NVIDIA vk_lod_clusters/RTX Mega Geometry 的簇级 BLAS 路线[^45^]可以让"虚拟化几何"与"RT 场景"共用一套 LOD 决策，UE 的 Lumen HWRT 与 MegaLights 共享 RT Scene 也是同一逻辑[^116^]。rurix 应在报告 1 的 P4 评审时回头看本节，决定簇级 BLAS 是否替代传统每网格 BLAS——这是七个方向中"几何×光追"最重要的汇流点。

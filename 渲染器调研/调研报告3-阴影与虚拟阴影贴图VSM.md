# 调研报告 3：阴影 / 虚拟阴影贴图（VSM）系统

> 面向 rurix（H:\rurix）的前沿论文与工业技术调研 · 2022–2026 · 出品日期：2026-07-28
>
> 本项目现状假设：自研引擎，已有 render graph/RHI、mesh/raster 与图形底座，尚无成熟的阴影缓存或虚拟化系统。本报告回答：技术清单、逐项（问题/算法/代价）、适配选择、分阶段路线（先基础 VSM/clipmap，再缓存、逐灯虚拟化、软阴影）、以及需要新增的 pass、缓冲、页表/缓存策略与验证方法。

## 结论摘要（TL;DR）

阴影方向 2022–2026 年的结论非常集中：**虚拟化已经成为高分辨率阴影的唯一工业答案**，其形态就是 UE5 的 Virtual Shadow Maps——把每盏灯的阴影空间当作 16K×16K 虚拟纹理，切成 128×128 页，按屏幕深度分析只分配并渲染被采样的页，页跨帧缓存、由移动图元/灯/级联切换失效[^98^]。方向光用 clipmap 栈（默认 6–22 级，覆盖 64cm–40km）解决大范围 LOD，聚光灯用单张 16K+mip 链，点光源用 6 面 cube[^98^]。软阴影的正解不是更大的 PCF 核，而是 **SMRT（Shadow Map Ray Tracing）**：沿光线方向对 VSM 做多次采样测试（默认 8 根光线、每线 4–8 次采样），用 Source Radius/Source Angle 控制半影，天然得到接触硬化效果[^98^]。

对 rurix 的落地判断：**VSM 的全部核心机制都可以脱离 Nanite 独立实现**，StratusGFX 的开源 Sparse VSM 给出了完整的最小实现参照（32 位页表项、稀疏纹理或共享池两种后端、环形更新标脏）[^114^]；与报告 1 的 Nanite 类几何系统对接后，阴影深度渲染可以复用同一套 cluster 剔除管线（UE 正是让 Nanite 的 CullRasterize 直接接受 VSM 虚拟目标并做 mip 视图压缩）[^109^]。推荐五阶段：**P0 单方向光 clipmap 基础 → P1 页缓存与失效 → P2 局部灯逐灯虚拟化 → P3 SMRT 软阴影+时域滤波 → P4 几何管线整合与平台预算**。P0–P1 只需常规 Vulkan 能力，P3 的 SMRT 是纯采样端算法，整条路线无硬件门槛。

## 2. 逐项分析：问题、算法与实现代价

### 2.1 VSM 核心：页表、页池、clipmap 与失效——"把阴影图当虚拟纹理管"

**要解决的问题。** 传统阴影图的分辨率×覆盖范围×显存是不可能三角：CSM 用 3–4 级级联在视野内切分，近处仍然锯齿、远处仍然浪费；逐灯独立阴影图则让多灯场景的显存与绘制调用爆炸。VSM 的破局点与虚拟纹理完全相同——**分辨率是虚拟的，物理分配是按页按需的**：16K×16K 只是地址空间，真正占用显存的只有当前帧被屏幕像素采样的 128×128 页[^98^]。

**核心算法。** 整套系统由四个机制咬合而成。其一，**页需求分析**：逐像素从主深度缓冲反投影到阴影空间，计算所需页坐标与 mip/clipmap 级，标记"used"并紧凑成 UAV 列表——UE 与 StratusGFX 均如此实现[^98^][^114^]。其二，**页表与页池**：每虚拟页一个 32 位页表项（帧标记、物理页索引、内存池索引、驻留位、脏位），物理页来自固定预算的页池（UE 实测 PS5 4096–8192 页区间调参）[^114^][^96^]。其三，**clipmap LOD**：方向光用一组以相机为中心、半径逐倍扩大的虚拟图（UE 默认 6–22 级，空级几乎免费），局部灯用单图+mip 链，按屏幕像素在阴影空间的投影尺寸选级[^98^]。其四，**失效与缓存**：页跨帧缓存，仅当页内图元移动/WPO 更新、灯移动、或级联原点切换时标脏重渲——**缓存命中的页几乎免费，失效的页成本≈传统阴影 pass+簿记**，全部优化都围绕"保持页缓存"展开[^96^]。

**实现代价。** StratusGFX 证明核心只需：2 个 compute pass（页标记、页压缩/分配）+1 个页表纹理+1 个物理页池+逐页投影光栅 pass[^114^]。真正的成本在**失效检测的事件管线**（场景图元变更→脏页队列）与**多视图光栅的剔除效率**（每 clipmap 级是一个视图，UE 在 GPU 上做空级压缩）[^109^][^115^]。对 rurix，这两块分别依赖场景系统（报告 6）与几何剔除管线（报告 1），因此排期上 P0/P1 用"保守失效+全量重渲"简化，P4 再做精细整合。

### 2.2 SMRT 软阴影与接触硬化——采样端算法，零新数据结构

**要解决的问题。** PCF 的本质缺陷是滤波核与几何无关：要软就得大核，大核就把高分辨率几何细节糊掉，且半影大小与遮挡物距离无关[^98^]。PCSS 用 blocker search 缓解了这一点，但仍有噪声与漏光。SMRT 换了个思路：**把面光源阴影当作一维积分**——从着色点向光源方向发若干根光线，每根光线沿途取若干样本投影到 VSM 测试遮挡，统计可见比例[^98^]。

**核心算法与代价。** 光线按光源的 Source Radius（局部灯）或 Source Angle（方向光）分布，Epic 画质档默认 8 根光线、每线 4–8 次 VSM 采样；`RayCount=0` 即退化为单样本硬阴影[^98^]。它与 PCSS 有相同的物理直觉（遮挡物越远半影越大），但因为沿光线连续采样，半影过渡自然且接触处锐利。实现上它**完全是着色端算法**：不需要新数据结构，只读页表+物理页池，可逐灯开关、逐档调参——这使它成为 rurix P3 阶段性价比极高的单项。噪声侧的补充手段是时域/空间滤波（见 2.4）。需要注意 SMRT 的固有局限：它测的是单张阴影投影而非真实几何，极端视角下会有投影近似误差[^98^]。

### 2.3 逐灯虚拟化与多灯阴影——VSM 的页池经济学 vs MegaLights 的随机路径

**要解决的问题。** 单一方向光的 VSM 之后，自然问题是：几十上百盏局部灯怎么办？这里 2024–2026 年出现了明确的分叉。UE 的 VSM 路线是**每灯一张虚拟图**（spot 单 16K+mip、point 六面 cube），全部灯共享同一物理页池，静态灯页长期缓存——实测每盏缓存灯仅约 0.05ms，可并存数十盏；但**移动灯全失效每盏 0.4–0.8ms**，实战规则是"移动局部灯预算 1–2 盏/帧"[^96^]。UE 5.5 还引入灯寿命管理（`MaxLightAgeSinceLastRequest`）防止僵尸灯把页表撑大、拖慢全部页表相关 pass[^115^]。

**核心算法与取舍。** MegaLights 给出另一答案：**阴影不该逐灯建图，而该逐像素抽样**——随机直接光管线按重要性采样选灯、直接向灯发光追线，阴影随求值一并完成，每灯零固定成本，代价是阴影质量依赖简化的 RT 场景表达；VSM 被保留为逐灯可选的高质量路径（全 Nanite 细节但只能近似面阴影，且每灯有 CPU/显存/GPU 三份固定开销）[^116^]。Epic 的实战建议因此是"绝大多数灯走 RT 阴影，只有强方向光等英雄灯走 VSM"[^116^]。对 rurix 的结论很直接：**P2 先做 VSM 逐灯虚拟化（与 RT 无关、立即可用），把 MegaLights 式随机阴影标记为长线项**，等报告 4 的 RT 闭环稳定后按 RTXDI/MegaLights 思路演进——两条路径共享同一个结论：方向光+英雄灯用 VSM，海量小灯用抽样。

### 2.4 阴影降噪与滤波——时域累积是免费午餐

**要解决的问题。** SMRT 的 8 根光线在硬核阴影边界仍有可见噪声；若未来引入 RT 阴影，1spp 的噪声更严重。两类场景的解法是同一套：**时域重投影累积 + 空间边缘保持滤波**。RT Gems 的光追阴影章节给出的配方是 4 帧时域盒滤波（样本集按 4 帧交错生成）+空间低通，并指出 SVGF/AI 降噪器可用但阴影专用简化版已够[^104^]；通用降噪管线的标准工序（速度场 prepass→累积→方差估计→à-trous 小波滤波 3–5 迭代、stepWidth 按 2 幂递减）同样适用于阴影可见性缓冲[^108^]。

**实现代价。** 很低：一张可见性历史纹理+重投影（rurix 的 TAA/报告 7 已需速度场，可复用）+一个 à-trous 计算 pass。收益直接换算成采样预算——4 帧时域交错等于把有效采样数乘 4，SMRT 可从 8 线降到 4 线保持同画质[^104^]。这是 P3 阶段务必与 SMRT 同批落地的组件。

### 2.5 与几何系统的关系——VSM 是 Nanite 类管线的第一个"多视图客户"

**关键事实。** UE 的 Nanite CullRasterize 直接接受 `FVirtualShadowMapArray` 作为虚拟目标：VSM 的每个 clipmap 级是一个 mip 视图，页表/页标志/页矩形边界以结构化缓冲传入，空 mip 视图在 GPU 上压缩剔除，两阶段遮挡剔除与 SW/HW 光栅原样复用，最后由 `BuildHZBFurthest` 建最远深度 HZB 供后置 pass[^109^]。这意味着**报告 1 的几何管线建成后，VSM 的阴影深度渲染几乎免费获得**——同一套 cluster 剔除以"多视图"模式跑进各脏页，远处 clipmap 级自动吃到 LOD 化简。UE5.7 实测反过来也成立：非 Nanite 网格走 VSM 页渲染的每失效页成本约为 Nanite 路径的 1.6 倍[^96^]。

**对 rurix 的推论。** 排期上 VSM（本报告 P0–P2）与 Nanite 类几何（报告 1 P0–P2）可以并行开发、在各自 P3/P4 合流：几何管线的多视图剔除接口应以"VSM 是客户之一"来设计（视图=主相机+N 个 clipmap 级+mip 视图），避免后期重构。UE 源码中 `MAX_VIEWS_PER_CULL_RASTERIZE_PASS` 的存在也提醒：视图数超上限要拆 pass，rurix 的剔除参数缓冲容量应按此上限规划[^109^]。

## 3. 适配 rurix 的选择推理

rurix"尚无成熟阴影缓存/虚拟化系统"的现状，意味着决策点不是"VSM 要不要"，而是"**VSM 的哪个子集先做、传统路径留多少**"。推荐取舍如下。第一，**方向光直接以 clipmap VSM 起步，不再建设 CSM**：CSM 的级联缝合、远级抖动问题在 clipmap 下全部消失，而 clipmap 只是 VSM 页表的一个寻址模式，不构成额外系统[^98^][^114^]。第二，**保留一条"传统逐灯小阴影图"回退路径**用于对拍验证与低端硬件，但不投入优化。第三，**软阴影一步到位选 SMRT**（而非 PCSS→SMRT 两步走），因为其增量只对着色端[^98^]。第四，**RT 阴影与 MegaLights 式抽样阴影列为长线**：它们与报告 4 共用 RT 底座，且 Epic 自己的结论就是"VSM 管英雄灯、抽样管海台灯"[^116^]。第五，**页池后端选型**：Vulkan 稀疏纹理（`VK_KHR_sparse_binding`）与共享纹理池二选一——StratusGFX 两种都支持，建议 rurix 用共享池起步（驱动行为更一致），稀疏纹理留作优化[^114^]。

一句话概括推荐路线：**以 StratusGFX SVSM 为骨架模板、以 UE VSM 文档为规格说明、以 UE5.5–5.7 优化项为调参清单**，按"clipmap 基础→缓存失效→逐灯虚拟化→SMRT+滤波→几何整合"五阶段推进。

## 5. 需要新增的 pass、缓冲、页表/缓存策略、验证方法

### 5.1 新增 pass 清单（全部 compute，除注明外）

| Pass | 输入 → 输出 | 阶段 |
|---|---|---|
| `shadow_page_mark` | 主深度缓冲+灯参数 → 页表 used 标记 | P1 |
| `shadow_page_alloc` | 页标记 → 紧凑请求列表+物理页分配/驱逐 | P1 |
| `shadow_invalidate` | 图元/灯变更事件 → 脏页标记 | P1 |
| `shadow_depth_raster`（图形/多视图） | 脏页列表 → 物理页池深度（逐页一个视图；P4 接 cluster 剔除） | P0/P4 |
| `shadow_view_compact` | mip 视图列表 → 非空视图压缩（GPU） | P4[^109^] |
| `shadow_project`（并入光照着色） | 页表+物理池+GBuffer → 阴影可见性（含 SMRT 采样） | P0/P3 |
| `shadow_filter` | 可见性缓冲+历史 → 时域累积+à-trous | P3 |

### 5.2 缓冲与资源布局

| 资源 | 形态 | 规模估算 | 生命周期 |
|---|---|---|---|
| 页表（每灯每级） | R32Uint 纹理/缓冲，64×64~128×128 项 | KB 级/灯 | 常驻，跨帧 |
| 物理页池 | R32Float（或深度格式）纹理数组，128²×N 页 | 4096 页 ≈ 256MB@R32（可按预算减至 2048/6144）[^96^][^114^] | 常驻 |
| 页请求/分配列表 | 结构化缓冲+计数器（UAV） | ≤页池容量 | graph transient |
| 脏页队列 | 结构化缓冲 | ≤页池容量 | graph transient |
| 可见性历史 | R8/R16 全屏纹理×2 | 屏幕分辨率 | 跨帧（P3） |
| mip/clipmap 视图参数 | 常量/结构化缓冲 | 级数×灯数 | 逐帧 |

### 5.3 页表/缓存策略要点

**分配策略**：页请求列表按优先级排序（近处 clipmap 级优先、新页优先于驱逐），页池满时按"最久未采样"驱逐——UE 5.5 的教训是驱逐粒度要包括整灯（灯寿命），否则页表本身成为性能瓶颈[^115^]。**失效策略**：图元移动/WPO 标脏其包围盒覆盖的全部页（按级遍历），灯移动标脏全图，级联原点切换标脏环形更新带；WPO 植被是失效风暴的头号来源，UE 实战对策是 WPO 距离禁用（15–30m 外不投阴影动画）[^96^][^115^]。**LOD 策略**：方向光 clipmap 级数按地平线距离裁剪（4km 可见地平线可把 LastLevel 从 22 降到 20，省 0.4–0.6ms 主机耗时），运动相机开 ResolutionLodBiasDirectionalMoving 自动降分辨率[^96^]。

### 5.4 验证方法

| 维度 | 方法 | 通过标准 |
|---|---|---|
| 精度 | 与传统高分辨率阴影图/参考渲染对拍（近、中、远三档距离） | 近处无毛刺锯齿；远处无闪烁 |
| 缓存正确性 | 静止相机逐帧对比：缓存渲染 vs 全量重渲染 | 逐像素一致（容差内） |
| 失效正确性 | 移动单个图元，检查仅预期页标脏（页表可视化） | 无误标/漏标；WPO 禁用半径外不动页 |
| 页池稳定性 | 相机大范围移动+灯开关压力序列 | 无持续驱逐颠簸；页命中率 >95%（稳态） |
| 软阴影质量 | 不同遮挡距离下半影宽度测量 vs 理论值；SMRT 采样数扫描 | 半影-距离关系单调正确；8 线档无可见噪声 |
| 性能 | 逐 pass GPU 计时+页统计（类 `r.Shadow.Virtual.ShowStats`[^115^]） | 阴影总预算达标（对齐 2.5–3.5ms@60Hz 主机档[^96^]） |
| 集成回归 | 与报告 1 几何管线多视图联测；与 TAA（报告 7）速度场联测 | 无同步错误；时域滤波无鬼影 |

## 6. 风险与缓解

**失效风暴是 VSM 的第一杀手**，UE 实战给出的画像非常具体：一棵带 WPO 风动画的灌木乘一万个实例可以在 PS5 上吃掉 6ms 阴影耗时[^96^]。缓解手段按优先级：WPO 距离禁用、植被小件不投动态阴影、失效事件合并去重、以及把"每帧失效页数"做成硬性预算与告警指标。**页池颠簸**是第二杀手：页池过小导致高频驱逐-重绘，表现为相机移动时阴影闪烁与耗时尖峰；对策是页池容量按平台分层（UE 实战 4096–8192 页）并把驱逐策略改为带帧龄延迟的 LRU[^96^][^114^]。

**与几何管线的耦合风险**在于时序：若报告 1 的 cluster 剔除延期，P4 会退化为"逐页全量光栅"，在重几何场景成本失控——因此 P0 的 `shadow_depth_raster` 接口必须第一天就按多视图设计，保证未来可无缝换芯[^109^]。**SMRT 的投影近似**在细长遮挡物+掠射角下会有可见误差，Epic 自己也标注了该局限[^98^]；缓解是保留 RT 阴影长线项（报告 4）作为英雄灯的升级路径。最后，**不要低估调试工具的价值**：页表/页池/clipmap 级的可视化（UE 的 VSM visualize 全套 viewmode）应在 P1 同步建设，否则失效问题几乎无法定位[^115^]。
